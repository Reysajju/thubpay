   259→  2658→### Stage 9 — Sandbox/dev-server instability (carries over from Phase 5)
   260→  2659→
   261→  2660→The dev server is OOM-killed reliably in this sandbox environment after 1-2 distinct route compiles. Memory: 4GB total, 0 swap. Turbopack and webpack dev compiles each take 50-90s and use 2+GB virtual memory; the kernel's cgroup OOM killer fires on the second compile (kernel ring buffer shows multiple `Out of memory: Killed process next-server` events). The Phase 5 worklog noted this same issue ("sandbox environment issue; not a code issue"). I was unable to run the full agent-browser QA sweep for this phase — the chrome processes alone consume 800MB+ RAM, leaving no room for both chrome and the dev server. Switching from Turbopack to webpack (`next dev --webpack`) reduced per-route compile time from ~50s to ~30s but did not prevent the OOM. Pre-building the production bundle (`next build`) succeeded after I fixed 8 pre-existing TS errors (Stage 1), but `next start` is also killed after handling 1-2 requests. Recommended next phase: profile memory usage and identify which compiled route is consuming the most RAM (likely the dashboard page with its many widgets, or the analytics page with chart rendering).
